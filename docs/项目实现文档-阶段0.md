## 0. 三条必须先说清的前提

### 0.1 关于"接入我的 API"

**我不是一个可调用的 LLM 服务。** 我是运行在你本机（DeepSeek Harness）里的编码助手，没有对外暴露的 API 端点，你的项目无法"接入我"。

你要做的是：**去 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys) 申请一个自己的 API key**，然后调用 DeepSeek 的公开 API。接口是 OpenAI 兼容协议，所以**换成任何其他厂商（阿里百炼、Kimi、智谱、OpenAI、本地 vLLM/Ollama）只需改 3 个配置项**。

> 已检查你的环境：目前**未配置任何 API key**（环境变量与 shell 配置里都没有）。这一步只能你自己做。

### 0.2 DeepSeek API 关键事实（已核实官方文档）

| 项目 | 值 | 对本项目的影响 |
| --- | --- | --- |
| Base URL（OpenAI 格式） | `https://api.deepseek.com` | 用 httpx 或 OpenAI SDK |
| 模型名 | `deepseek-flash`、`deepseek-v4-pro` | **用新名**，旧名 `deepseek-v4-flash` 已下线 |
| 上下文长度 | 1M tokens | 够用，但**不要因此把整篇文档塞进 prompt**（成本随输入线性增长） |
| 能力 | JSON Output ✅、Tool Calls ✅、默认开启思考模式 | 阶段 5 的 Agent 靠 Tool Calls |
| 图像理解 | 仅 `deepseek-flash` | 阶段 3 解析 PDF/图片时有用 |
| 并发限制 | flash 2500 / pro 500（**按账号计，与 key 无关**） | 个人项目够用；生产要设客户端上限 |
| 超并发 | HTTP 429 | 必须指数退避重试 |
| `user_id` 参数 | 正则 `[a-zA-Z0-9\-_]+`，≤512 字符，**不可含隐私信息** | 多用户隔离 + KVCache 隔离 |
| 保活机制 | 非流式持续返回**空行**；流式返回 SSE 注释 `: keep-alive` | **自己解析响应时必须跳过**，否则 JSON 解析炸 |
| 超时 | 10 分钟未开始推理则服务端断开 | 客户端超时要小于它 |

**价格（元/百万 tokens；高峰 = 工作日 9-12、14-18 点，空闲价为高峰一半）**：

| 模型 | 输入(缓存命中) | 输入(未命中) | 输出 |
| --- | --- | --- | --- |
| `deepseek-flash` | 空闲 0.02 / 高峰 0.04 | 空闲 1 / 高峰 2 | 空闲 4 / 高峰 8 |
| `deepseek-v4-pro` | 空闲 0.15 / 高峰 0.30 | 空闲 4.5 / 高峰 9 | 空闲 13.5 / 高峰 27 |

**三条直接决定设计的推论**：

1. **缓存命中价差 50 倍**（1 元 vs 0.02 元）→ 系统提示词必须是**固定文本**，放在消息数组最前面。绝不能塞时间戳、随机 ID，否则缓存永不命中，成本直接涨 50 倍。这是设计约束，不是优化技巧。
2. **输出比输入贵 4 倍** → 明确要求"简洁回答"、设 `max_tokens`，就是省钱。
3. **空闲时段半价** → 批量任务（阶段 3 的 embedding、阶段 6 的评测跑批）安排到夜间/周末，成本立省 50%。

### 0.2.1 ★ 实测发现：思考模式必须默认关闭（阶段 0 最重要的调优）

上面三条是读文档得到的，这一条是**真实测出来的**，而且影响最大。

DeepSeek **默认开启思考模式且 `reasoning_effort=high`**。思维链 token 会被计入 `completion_tokens` 并按输出价（4 元/M）计费。我做了对照实验（同一 RAG 问答 prompt）：

| 模式 | completion | 其中思考 | 耗时 | 单次成本 | 答案 |
| --- | --- | --- | --- | --- | --- |
| `enabled`（API 默认） | 187 | 151 | 1733ms | ≈0.00188 元 | 正确 |
| `disabled` | 36 | — | 703ms | ≈0.00049 元 | **同样正确** |

**关闭后：成本降到 1/4，延迟降低 60%，质量没有下降。**

**为什么 RAG 场景应该关闭**：思考模式是为数学、代码、多步逻辑推理设计的。而 RAG 问答干的是"从已检索到的资料里提取并总结"——**推理在检索阶段就完成了**，模型不需要再"想"。真要让答案更好，应该去优化切片和召回（阶段 4），而不是让模型对着资料空想。

**落地方式**（已实现）：

```python
# .env
LLM_THINKING=false          # 阶段 0 默认关闭
LLM_REASONING_EFFORT=low    # 若打开思考，用 low 而不是默认的 high
```

```python
# app/clients/llm.py
payload["thinking"] = {"type": "enabled" if thinking else "disabled"}
if thinking:
    payload["reasoning_effort"] = settings.llm_reasoning_effort
else:
    payload["temperature"] = temperature   # 思考模式下 temperature 会被静默忽略
```

### 0.2.2 ★ 实测发现：temperature 在思考模式下是"假参数"

官方文档明确：**思考模式不支持 `temperature`、`presence_penalty`、`frequency_penalty`。设置这些参数不会报错，但也不会生效。**

也就是说，网上大量 FastAPI + LLM 教程里写的 `temperature=0.2`，在思考模式下**完全是个摆设**——你以为在控制随机性，其实没有。这也是上面代码里把 `temperature` 放进 `else` 分支的原因：**只在关闭思考时才传它，避免制造"我设了但没生效"的错觉。**

### 0.2.3 ★ 实测发现：缓存确实生效，但按 512 token 块命中

我实测了三次相同 prompt（933 字符的参考资料）：

| 调用 | prompt | cached | miss | 成本 |
| --- | --- | --- | --- | --- |
| 第 1 次 | 668 | 0 | 668 | 0.002536 |
| 第 2 次 | 668 | **512** | 156 | 0.001532 |
| 第 3 次 | 668 | **512** | 156 | 0.001532 |

**两个结论**：
1. **缓存机制真实有效**，第 2 次起稳定命中 512 token，成本下降约 40%（不是 50 倍——因为输出成本和未命中的那部分输入成本仍在）。
2. **缓存按 512 token 块命中**，所以短 prompt（我第一次用 50 token 测）**永远命中不了**。这意味着：**系统提示词 + 资料前缀必须够长，缓存才有意义**。如果阶段 1 想把缓存利用率做上去，可以把稳定不变的规则文档拼在 system prompt 里，让它稳定超过 512 的整数倍。

响应里两个字段会同时出现，任取其一即可：

```json
"prompt_cache_hit_tokens": 512,
"prompt_tokens_details": {"cached_tokens": 512}
```

### 1.2 ❌ 致命坑：`passlib` 不能用，会直接崩

如果你照着网上任何一篇 FastAPI 认证教程写，第一行就会是 `pip install "passlib[bcrypt]"`。**在你的环境下这会直接报错**，实测原始输出：

```
(trapped) error reading bcrypt version
AttributeError: module 'bcrypt' has no attribute '__about__'
ValueError: password cannot be longer than 72 bytes, truncate manually if necessary
```

**根因**：`passlib` 最后发布于 **2020 年**（1.7.4），它靠读取 `bcrypt.__about__.__version__` 来判断版本，而 `bcrypt` 在 4.x 就删掉了 `__about__`（现在是 5.0.0）。passlib 遇到读不到的版本号会走错分支，最终在 `ctx.hash()` 抛 `ValueError`。

**解决方案：直接用 `bcrypt` 库，不要 passlib。** 实测通过：

```python
# app/core/security.py
"""密码哈希：直接用 bcrypt，不用 passlib（passlib 1.7.4 与 bcrypt 5.x 不兼容）。"""

import bcrypt
from fastapi import HTTPException, status

# bcrypt 的硬限制：超过 72 字节的部分会被静默截断，所以必须显式拦截
MAX_PASSWORD_BYTES = 72


def hash_password(password: str) -> str:
    raw = password.encode("utf-8")
    if len(raw) > MAX_PASSWORD_BYTES:
        # 不要静默截断——那会让超长密码的前 72 字节相同就能登录
        raise HTTPException(
            status_code=status.HTTP_422_UNPROCESSABLE_ENTITY,
            detail=f"密码长度不能超过 {MAX_PASSWORD_BYTES} 字节",
        )
    return bcrypt.hashpw(raw, bcrypt.gensalt()).decode("utf-8")


def verify_password(password: str, hashed: str) -> bool:
    raw = password.encode("utf-8")
    if len(raw) > MAX_PASSWORD_BYTES:
        return False
    try:
        return bcrypt.checkpw(raw, hashed.encode("utf-8"))
    except ValueError:
        # 哈希串格式非法（例如库里存了脏数据）
        return False
```

> 顺带说明：这条坑值得写进你的学习笔记。**"教程里的依赖组合可能已经过期"**是工程中的常态，遇到 `AttributeError: module 'x' has no attribute '__about__'` 这类错，第一反应应该是查两边的发版时间差，而不是怀疑自己的代码。

### 1.3 ✅ JWT：`python-jose` 可用，但推荐 `PyJWT`

两者实测都能正常签发/校验。推荐 **PyJWT**，原因是实测时它主动给出了一个安全警告：

```
InsecureKeyLengthWarning: The HMAC key is 6 bytes long,
which is below the minimum recommended length of 32 bytes for SHA256.
```

`python-jose` 对弱密钥**沉默**，PyJWT 会**警告你**。在安全相关的地方，会报错的库比不报错的库好。而且 PyJWT 维护更活跃。

```bash
uv add pyjwt
```

```python
from sqlalchemy import ForeignKey, Integer, Text
from sqlalchemy.orm import Mapped, mapped_column, relationship

from app.models.base import Base


class Chunk(Base):
    __tablename__ = "chunks"

    id: Mapped[int] = mapped_column(primary_key=True)

        ForeignKey("documents.id", ondelete="CASCADE"), index=True

    content: Mapped[str] = mapped_column(Text)

    document: Mapped["Document"] = relationship(back_populates="chunks")
```

```python
    owner_id: Mapped[int] = mapped_column(ForeignKey("users.id"), index=True)
    question: Mapped[str] = mapped_column(Text)
    answer: Mapped[str] = mapped_column(Text)
    prompt_tokens: Mapped[int] = mapped_column(Integer, default=0)
    completion_tokens: Mapped[int] = mapped_column(Integer, default=0)
    cached_tokens: Mapped[int] = mapped_column(Integer, default=0)
    cost_yuan: Mapped[float] = mapped_column(Float, default=0.0)
    latency_ms: Mapped[int] = mapped_column(Integer, default=0)
    model: Mapped[str] = mapped_column(String(50), default="")
    is_off_peak: Mapped[bool] = mapped_column(Boolean, default=False)
    cited_chunk_ids: Mapped[list[int]] = mapped_column(JSON, default=list)
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now()
    )
```

**三个刻意的决定**：
- `chunks.owner_id` 冗余 → 权限过滤不用 join
- `chat_logs` 第 0 天就有 → 阶段 6 做评估时没有历史数据就只能干瞪眼
- `documents.status` 第 0 天就加 → 阶段 3 引入异步任务时不用改表结构

### 6.2 成本计算

```python
# app/clients/pricing.py
"""DeepSeek 价格表（元/百万 tokens）。核实于 2026 年，官方定价页会变动，用前请核对。"""

from dataclasses import dataclass
from datetime import datetime, time
from zoneinfo import ZoneInfo


@dataclass(frozen=True)
class ModelPrice:
    input_cached: float
    input_miss: float
    output: float


# 空闲时段价格（高峰为其 2 倍）
PRICES: dict[str, ModelPrice] = {
    "deepseek-flash": ModelPrice(input_cached=0.02, input_miss=1.0, output=4.0),
    "deepseek-v4-pro": ModelPrice(input_cached=0.15, input_miss=4.5, output=13.5),
}

CST = ZoneInfo("Asia/Shanghai")


def is_peak_now(now: datetime | None = None) -> bool:
    """高峰：北京时间周一至周五 9:00-12:00、14:00-18:00（未处理法定节假日）。"""
    now = now or datetime.now(CST)
    if now.weekday() >= 5:
        return False
    t = now.time()
    return (time(9, 0) <= t < time(12, 0)) or (time(14, 0) <= t < time(18, 0))


def calc_cost(
    model: str,
    prompt_tokens: int,
    completion_tokens: int,
    cached_tokens: int = 0,
    peak: bool | None = None,
) -> float:
    price = PRICES.get(model)
    if price is None:
        return 0.0
    peak = is_peak_now() if peak is None else peak
    multiplier = 2.0 if peak else 1.0
    miss = max(prompt_tokens - cached_tokens, 0)
    cost = (
        cached_tokens * price.input_cached
        + miss * price.input_miss
        + completion_tokens * price.output
    ) / 1_000_000
    return round(cost * multiplier, 6)
```

> `cached_tokens` 取自响应的 usage 字段。**不同版本字段名可能有差异，第一次真实调用时把完整响应打印出来对齐字段名**，这决定你的成本算得准不准。

### 6.3 客户端实现

```python
# app/clients/llm.py
"""唯一的 LLM 出口。业务层只调 chat()，不碰 HTTP。"""

import asyncio
import logging
import time
from dataclasses import dataclass, field

import httpx

from app.clients.pricing import calc_cost, is_peak_now
from app.core.config import settings

logger = logging.getLogger(__name__)

RETRYABLE_STATUS = {408, 429, 500, 502, 503, 504}


class LLMError(RuntimeError):
    """LLM 调用失败的统一异常，业务层只需捕获它。"""

    def __init__(self, message: str, *, status_code: int | None = None, retryable: bool = False):
        super().__init__(message)
        self.status_code = status_code
        self.retryable = retryable


@dataclass
class LLMResult:
    content: str
    prompt_tokens: int = 0
    completion_tokens: int = 0
    cached_tokens: int = 0
    latency_ms: int = 0
    model: str = ""
    cost_yuan: float = 0.0
    peak: bool = False
    raw: dict = field(default_factory=dict)


class LLMClient:
    def __init__(self) -> None:
        self._client: httpx.AsyncClient | None = None

    async def startup(self) -> None:
        self._client = httpx.AsyncClient(
            base_url=settings.llm_base_url,
            timeout=httpx.Timeout(
                connect=5.0,
                read=settings.llm_timeout_seconds,   # 必须 < 服务端 10 分钟保活上限
                write=30.0,
                pool=5.0,
            ),
            limits=httpx.Limits(max_connections=50, max_keepalive_connections=10),
            headers={
                "Authorization": f"Bearer {settings.llm_api_key}",
                "Content-Type": "application/json",
            },
        )

    async def shutdown(self) -> None:
        if self._client is not None:
            await self._client.aclose()
            self._client = None

    @property
    def client(self) -> httpx.AsyncClient:
        if self._client is None:
            raise RuntimeError("LLMClient 未初始化：请在 lifespan 中 await startup()")
        return self._client

    async def chat(
        self,
        messages: list[dict[str, str]],
        *,
        temperature: float = 0.3,
        max_tokens: int | None = None,
        user_id: str | None = None,
        json_mode: bool = False,
    ) -> LLMResult:
        payload: dict = {
            "model": settings.llm_model,
            "messages": messages,
            "temperature": temperature,
            "max_tokens": max_tokens or settings.llm_max_tokens,
            "stream": False,
        }
        if json_mode:
            payload["response_format"] = {"type": "json_object"}
        if user_id:
            # DeepSeek 扩展：多用户隔离 + KVCache 隔离。不可含隐私信息。
            payload["user_id"] = user_id

        start = time.perf_counter()
        last_exc: Exception | None = None

        for attempt in range(1, settings.llm_max_retries + 1):
            try:
                resp = await self.client.post("/chat/completions", json=payload)
            except httpx.TimeoutException:
                last_exc = LLMError("LLM 请求超时", retryable=True)
                logger.warning("LLM 超时 attempt=%s", attempt)
            except httpx.RequestError as exc:
                last_exc = LLMError(f"LLM 网络错误: {exc}", retryable=True)
                logger.warning("LLM 网络错误 attempt=%s: %s", attempt, exc)
            else:
                if resp.status_code == 200:
                    return self._parse(resp.json(), start)
                if resp.status_code in RETRYABLE_STATUS:
                    last_exc = LLMError(
                        f"LLM 返回 {resp.status_code}: {resp.text[:300]}",
                        status_code=resp.status_code,
                        retryable=True,
                    )
                else:
                    # 4xx（除 408/429）是请求本身有问题，重试无意义
                    raise LLMError(
                        f"LLM 请求失败 {resp.status_code}: {resp.text[:300]}",
                        status_code=resp.status_code,
                        retryable=False,
                    )

            if attempt < settings.llm_max_retries:
                delay = min(2 ** (attempt - 1) * 0.5, 8.0)
                delay += time.perf_counter() % 0.3     # 抖动，避免 429 时齐步重试
                await asyncio.sleep(delay)

        raise last_exc or LLMError("LLM 调用失败")

    def _parse(self, data: dict, start: float) -> LLMResult:
        latency_ms = int((time.perf_counter() - start) * 1000)
        choice = (data.get("choices") or [{}])[0]
        content = (choice.get("message") or {}).get("content") or ""
        usage = data.get("usage") or {}

        prompt_tokens = int(usage.get("prompt_tokens") or 0)
        completion_tokens = int(usage.get("completion_tokens") or 0)
        cached_tokens = int(
            usage.get("prompt_cache_hit_tokens")
            or (usage.get("prompt_tokens_details") or {}).get("cached_tokens")
            or 0
        )
        model = data.get("model") or settings.llm_model
        peak = is_peak_now()

        return LLMResult(
            content=content,
            prompt_tokens=prompt_tokens,
            completion_tokens=completion_tokens,
            cached_tokens=cached_tokens,
            latency_ms=latency_ms,
            model=model,
            cost_yuan=calc_cost(model, prompt_tokens, completion_tokens, cached_tokens, peak),
            peak=peak,
            raw=data,
        )


llm_client = LLMClient()


async def get_llm() -> LLMClient:
    """FastAPI 依赖，方便测试整体替换。"""
    return llm_client
```

### 6.4 三个必须注意的坑

1. **保活内容**：DeepSeek 等待推理时持续返回**空行**（非流式）或 `: keep-alive`（流式）。用 `httpx` + `resp.json()` 没问题，但阶段 2 自己解析 SSE 时**必须先过滤空行和 `:` 开头的行**。
2. **绝不用 `requests`**：`async def` 里调用同步库会阻塞事件循环。必须 `httpx.AsyncClient`。
3. **客户端必须单例**：在 `lifespan` 里 startup/shutdown。每请求新建会让 TLS 握手开销让延迟翻倍。

### 7.1 切片

```python
# app/services/ingest.py
"""文档解析与切片。阶段 0 只支持 txt/md，按字符切分。"""

import re
from dataclasses import dataclass

from app.core.config import settings


@dataclass
class ChunkDraft:
    seq: int
    content: str


def normalize(text: str) -> str:
    text = text.replace("\r\n", "\n").replace("\r", "\n")
    text = re.sub(r"\n{3,}", "\n\n", text)
    return text.strip()


def split_text(
    text: str, chunk_size: int | None = None, overlap: int | None = None
) -> list[ChunkDraft]:
    """按段落聚合切片，超长段落内部再切，相邻切片保留 overlap 重叠。

    为什么按段落而不是硬切 N 个字符：
    硬切会把一句话、一张表拦腰截断，检索到的片段语义不完整，模型容易答错。
    阶段 4 会在此基础上加"按标题层级切分"，但段落优先的原则不变。
    """
    chunk_size = chunk_size or settings.chunk_size
    overlap = overlap or settings.chunk_overlap
    text = normalize(text)
    if not text:
        return []

    paragraphs = [p.strip() for p in text.split("\n\n") if p.strip()]
    drafts: list[ChunkDraft] = []
    buf = ""

    def flush() -> None:
        nonlocal buf
        if buf.strip():
            drafts.append(ChunkDraft(seq=len(drafts), content=buf.strip()))
        buf = ""

    for para in paragraphs:
        if len(para) > chunk_size:
            flush()
            start = 0
            while start < len(para):
                piece = para[start:start + chunk_size]
                drafts.append(ChunkDraft(seq=len(drafts), content=piece))
                if start + chunk_size >= len(para):
                    break
                start += chunk_size - overlap
            continue

        if len(buf) + len(para) + 2 <= chunk_size:
            buf = f"{buf}\n\n{para}" if buf else para
        else:
            flush()
            buf = para

    flush()

    # 段落聚合产生的相邻切片之间补重叠，避免跨片语义断裂
    if overlap > 0 and len(drafts) > 1:
        for i in range(1, len(drafts)):
            prev_tail = drafts[i - 1].content[-overlap:]
            if prev_tail and not drafts[i].content.startswith(prev_tail):
                drafts[i] = ChunkDraft(
                    seq=drafts[i].seq, content=f"{prev_tail}\n\n{drafts[i].content}"
                )

    return drafts
```

**这是纯函数，必须写单测**（`test_chunking.py`）：空文本、单段落、超长段落、恰好等于 chunk_size、含大量空行这些边界都要覆盖。

### 7.2 检索

```python
# app/services/retrieval.py
"""检索层。阶段 0 = 关键词匹配；阶段 4 换向量+混合检索，签名保持不变。"""

from dataclasses import dataclass

from sqlalchemy import or_, select
from sqlalchemy.ext.asyncio import AsyncSession

from app.core.config import settings
from app.models.chunk import Chunk
from app.models.document import Document


@dataclass
class RetrievedChunk:
    chunk_id: int
    document_id: int
    document_title: str
    seq: int
    content: str
    score: float = 0.0


def _keywords(question: str) -> list[str]:
    """极简分词：英文按空格，中文按 2-gram。够用，阶段 4 会被向量检索取代。"""
    tokens: list[str] = [w.strip() for w in question.split() if w.strip()]
    chinese = "".join(ch for ch in question if "\u4e00" <= ch <= "\u9fff")
    tokens += [chinese[i:i + 2] for i in range(len(chinese) - 1)]
    return list({t for t in tokens if len(t) >= 2})[:20]


async def search(
    db: AsyncSession, *, owner_id: int, question: str, top_k: int | None = None
) -> list[RetrievedChunk]:
    top_k = top_k or settings.retrieval_top_k
    tokens = _keywords(question)
    if not tokens:
        return []

    conditions = [Chunk.content.ilike(f"%{t}%") for t in tokens]
    stmt = (
        select(Chunk, Document.title)
        .join(Document, Document.id == Chunk.document_id)
        .where(Chunk.owner_id == owner_id)      # ★ 权限过滤：绝不返回别人的文档
        .where(or_(*conditions))
        .limit(top_k * 4)                       # 多取一些，再按命中数重排
    )
    rows = (await db.execute(stmt)).all()

    results = [
        RetrievedChunk(
            chunk_id=chunk.id,
            document_id=chunk.document_id,
            document_title=title,
            seq=chunk.seq,
            content=chunk.content,
            score=float(sum(1 for t in tokens if t in chunk.content)),
        )
        for chunk, title in rows
    ]
    results.sort(key=lambda r: (-r.score, r.chunk_id))
    return results[:top_k]
```

### 7.3 问答编排

```python
# app/services/qa.py
"""拼 prompt → 调 LLM → 组装引用。阶段 0 的业务核心。"""

import asyncio

from sqlalchemy.ext.asyncio import AsyncSession

from app.clients.llm import LLMClient
from app.core.config import settings
from app.models.chat_log import ChatLog
from app.services.retrieval import RetrievedChunk, search

# ★ 必须是固定文本（无时间戳、无随机值），否则永远吃不到缓存，成本差 50 倍
SYSTEM_PROMPT = """你是一个严谨的知识库问答助手。请遵守以下规则：

1. 只根据【参考资料】回答，不要使用你自己的知识补充事实。
2. 如果参考资料不足以回答，直接回答"根据现有资料无法回答"，不要编造。
3. 回答简洁准确，不要复述问题，不要输出与问题无关的内容。
4. 在引用具体内容时，用 [1] [2] 的形式标注来源编号。
"""

_llm_semaphore = asyncio.Semaphore(10)   # 单进程最多 10 个并发 LLM 请求

# 进程内信号量在多 worker 部署下会失效（每个 worker 各有一份），
# 阶段 1 引入 Redis 后换成分布式限流。现在用它防开发时把自己打爆。


def build_context(chunks: list[RetrievedChunk], max_chars: int | None = None) -> str:
    max_chars = max_chars or settings.max_context_chars
    parts: list[str] = []
    used = 0
    for i, c in enumerate(chunks, start=1):
        block = f"[{i}] 来源：《{c.document_title}》第 {c.seq + 1} 段\n{c.content}"
        if used + len(block) > max_chars:
            break
        parts.append(block)
        used += len(block)
    return "\n\n".join(parts)


async def answer(
    db: AsyncSession,
    llm: LLMClient,
    *,
    owner_id: int,
    question: str,
    top_k: int | None = None,
) -> tuple[str, list[RetrievedChunk], dict]:
    chunks = await search(db, owner_id=owner_id, question=question, top_k=top_k)

    if not chunks:
        return (
            "知识库中没有找到与该问题相关的内容。请先上传相关文档，或换一种问法。",
            [],
            {"prompt_tokens": 0, "completion_tokens": 0, "cost_yuan": 0.0, "latency_ms": 0},
        )

    context = build_context(chunks)
    user_prompt = f"""【参考资料】
{context}

【问题】
{question}

请根据参考资料回答，并标注引用编号。"""

    async with _llm_semaphore:
        result = await llm.chat(
            [
                {"role": "system", "content": SYSTEM_PROMPT},
                {"role": "user", "content": user_prompt},
            ],
            temperature=0.2,
            user_id=f"u{owner_id}",     # 隔离用，不含隐私信息
        )

    db.add(
        ChatLog(
            owner_id=owner_id,
            question=question,
            answer=result.content,
            prompt_tokens=result.prompt_tokens,
            completion_tokens=result.completion_tokens,
            cached_tokens=result.cached_tokens,
            cost_yuan=result.cost_yuan,
            latency_ms=result.latency_ms,
            model=result.model,
            is_off_peak=not result.peak,
            cited_chunk_ids=[c.chunk_id for c in chunks],
        )
    )

    usage = {
        "prompt_tokens": result.prompt_tokens,
        "completion_tokens": result.completion_tokens,
        "cost_yuan": result.cost_yuan,
        "latency_ms": result.latency_ms,
    }
    return result.content, chunks, usage
```

**为什么 `SYSTEM_PROMPT` 必须是固定常量**：缓存命中价是未命中的 1/50。一旦塞进 `f"当前时间：{now}"`，缓存全部失效，同样的请求成本直接涨 50 倍。

```python
# app/core/exceptions.py
import logging

from fastapi import FastAPI, Request, status
from fastapi.responses import JSONResponse

from app.clients.llm import LLMError

logger = logging.getLogger(__name__)


class BizError(Exception):
    def __init__(self, message: str, code: int = 40000, http_status: int = 400):
        self.message, self.code, self.http_status = message, code, http_status


def register_exception_handlers(app: FastAPI) -> None:
    @app.exception_handler(BizError)
    async def _biz(request: Request, exc: BizError):
        return JSONResponse(
            status_code=exc.http_status,
            content={"code": exc.code, "message": exc.message, "detail": None},
        )

    @app.exception_handler(LLMError)
    async def _llm(request: Request, exc: LLMError):
        logger.error("LLM 调用失败: %s", exc)
        return JSONResponse(
            status_code=status.HTTP_502_BAD_GATEWAY,
            content={"code": 50201, "message": "AI 服务暂时不可用，请稍后重试", "detail": None},
        )
```

## 9. 测试策略

**核心原则：单元/集成测试绝不真实调用 LLM。** 原因不是省钱，而是**不可重复**——模型输出有随机性，测试会随机红绿。

```python
# app/tests/conftest.py

from httpx import ASGITransport, AsyncClient
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine

from app.db.session import get_db
from app.main import app

class FakeLLM:
```

## 12. 阶段 0 验收清单

**任何一项没做到，不要进入阶段 1**：

- [ ] `pytest -q` 全绿，且**断网也全绿**（证明没有隐藏的真实调用）
- [ ] 真实 LLM 冒烟测试通过，且已把真实 `usage` 结构回填到 `_parse()`
- [ ] 上传 md → 提问 → 得到带 `[1]` 引用的答案，`citations` 里能看到具体文档和段落
- [ ] 提问知识库里没有的内容 → 明确回答"无法回答"，**没有编造**
- [ ] 用户 A 无法检索到用户 B 的文档（有测试覆盖）
- [ ] 上传 .pdf 返回 415（阶段 0 明确不支持，必须明确报错而非静默失败）
- [ ] `chat_logs` 表有完整记录：token 数、缓存命中数、成本、延迟、引用切片
- [ ] 能跑出 §10 那三条 SQL 并读懂结果
- [ ] 故意把 `LLM_API_KEY` 改错 → 返回 502 + 友好提示，**不是 500 堆栈**
- [ ] 在本文档或项目 README 里记下你踩的坑

**最后一条最重要**：现在写下踩的坑，三个月后写简历和面试时你会感谢自己。已知你会踩的两个（§1.2 的 passlib、§6.4 的保活空行）我已经替你标出来了，自己再遇到的才是真正值钱的。

### 12.1 阶段 1 引入 Redis 后，必须回头补的三条回归测试

这三条是**阶段 1 的改动会打破阶段 0 既有保证**的地方。加缓存本身不难，难的是别把已经做对的事情弄坏——所以它们必须在阶段 1 完成时同时存在（详见[阶段 1 文档 §10.2](项目实现文档-阶段1.md)）：

- [ ] **用户 A 与用户 B 问同一个问题 → 缓存键必须不同**（缓存键漏掉 `owner_id` 会直接变成跨用户数据泄露，这是安全事故级）
- [ ] **上传了相关新文档后，同一问题不再命中缓存**（否则会出现"文档改了但答案永远不变"的严重误导）
- [ ] **缓存命中的请求不消耗每日 LLM 配额**（否则缓存省下的成本又被配额扣掉，逻辑自相矛盾）

> 这三条的共同点：**它们都不是"新功能"，而是"新功能不能破坏旧保证"**。软件工程里绝大多数严重 bug 都属于这一类。养成习惯——每次加一层能力时，先问一句"我这次改动可能弄坏什么"。

## 13. 升级钩子（后续阶段改哪里，不用猜）

| 阶段 | 加什么 | 改动位置 | 是否改接口契约 |
| --- | --- | --- | --- |
| 1 | Redis 缓存 + 分布式限流 | 新增 `clients/cache.py`；`retrieval.py` 加缓存层；信号量换 Redis 限流 | 不改 |
