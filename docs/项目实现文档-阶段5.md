## 1. ★★ 实测结论（写代码前必须知道）

### 1.1 ★ **更正**：阶段 4 预警的 `reasoning_content` 硬约束**不成立**

我在阶段 4 文档 §12.1 写过一条预警：

> 请求携带 `tools` 参数时，后续所有轮次必须完整回传 `reasoning_content`，否则 API 直接返回 400。

**阶段 5 开工前的实测推翻了它。** 我用 `httpx` 直接验证：

| 实验 | 做法 | 结果 |
| --- | --- | --- |
| 1 | 带 `tools` + 思考模式，**正确**回传 `reasoning_content` | HTTP 200 ✅ |
| 2 | 带 `tools` + 思考模式，**故意不回传** | **HTTP 200**（未报错）❗ |
| 3 | **多轮**工具调用（3 轮），全程不回传 | **全程 200** ✅ |

**结论**：当前 API 版本下不回传 `reasoning_content` **不会报 400**。那条预警可能来自旧版本，或只在特定组合下成立。

**但这不意味着应该省略它**——两者的区别很重要：

| | 状态 | 该怎么做 |
| --- | --- | --- |
| **不报 400** | ✅ 已实测确认 | 不必为此加防御性代码或 try/except |
| **回传能提升质量** | 合理推断（让模型复用上一轮推理） | **建议回传**，作为质量优化而非兼容性要求 |

所以本阶段的设计是：**回传 `reasoning_content`，但在文档里标明这是质量优化、不是硬要求**。如果哪天它真的开始报 400，你已经做对了。

> **这个更正本身就是一条经验**：阶段 4 的预警来自官方文档的当前表述，但**实测才是准的**。凡是要为某条约束写防御代码之前，先花 5 分钟实测它是否真的存在。

### 1.2 观察到的两个真实失败模式

我在验证工具调用时顺带观察到两个会在生产里出现的问题：

**失败模式 1：工具描述重叠 → 错调/多调**

我给了两个工具（`get_weather` 查天气、`get_date` 查日期），问"杭州今天天气怎么样"，模型**先调了 `get_date`**——因为"今天"让它觉得日期工具有用。

**另一个例子**：给了 `search_kb` 和 `calc`，问"帮我检索「退款」"，模型连续两轮都在调 `search_kb`（第二轮是因为我的假工具返回了参数错误）。

**对策**：工具描述必须**互斥**，而且要**显式写明"什么时候不要用"**：

```python
# ❌ 模糊
{"name": "calc", "description": "计算数学表达式"}

# ✅ 明确边界与禁用场景
{"name": "calc",
 "description": "对数学表达式求值。仅在需要精确数值计算时使用（如折扣、单价×数量、百分比）。"
                "不要用它做单位换算以外的推理，也不要用它查资料——查资料请用 search_kb。"}
```

**失败模式 2：工具报错时模型会自我修正（前提是错误可读）**

我故意让工具返回"错误：缺少必填参数 query"，模型的反应是：

```
"检索时提示缺少必填参数 query，看起来是调用格式没被正确识别。我重新发起一次检索："
→ 然后正确地重新调用了工具
```

**对策**：**工具错误必须以可读文本返回给模型，而不是抛异常让循环中断。**

```python
# ❌ 抛异常 → 整个 agent 循环崩掉，用户看到一个 500
raise ToolError("缺少必填参数 query")

# ✅ 作为工具结果返回 → 模型能读懂并自我修正
return {"error": "缺少必填参数 query（应提供字符串）"}
```

**这是本阶段最实用的一条设计原则**：**把错误当成工具输出的一部分**，而不是当成异常。

### 1.3 ★ 写文档时的实测发现：`OverflowError` 会崩掉整个循环

我在写本文档的 `calc` 工具时，先写了"防 `2**10**10` 这类计算爆炸"的保护，然后**实测验证它**——结果发现**那个保护是无效的**：

| 表达式 | 结果 | 说明 |
| --- | --- | --- |
| `2**10` | OK 1024 | 正常 |
| `2**1000` | 抛 `OverflowError` | `float()` 转换溢出 |
| `2**100000` / `2**10**10` / `9**9**9` | **抛 `OverflowError`（0.00 秒）** | 不会卡死，但异常类型是 `OverflowError` |

**问题**：我最初的 `except` 只写了 `(SyntaxError, ValueError, TypeError)` —— **`OverflowError` 不在其中，它会逃出工具、冒泡到 agent 循环、最终变成 500**。

**实测证据**：我写了个对比脚本同时跑"文档原版"和"修正版"，跑原版时**脚本本身崩了**：

```
File "<stdin>", line 45, in <module>
    o, f = tool_original(e), tool_fixed(e)
File "<stdin>", line 32, in tool_original
OverflowError: (34, 'Result too large')
```

**修正两处**（都已落到本文档 §4.3 的完整代码里，此处只示意改动点）：

```diff
  if isinstance(node, ast.BinOp) and type(node.op) in _OPS:
+     # ① 在**计算之前**限制指数大小（比事后判断结果更早、更省）
+     if isinstance(node.op, ast.Pow):
+         right = node.right
+         if not (isinstance(right, ast.Constant)
+                 and isinstance(right.value, int)
+                 and abs(right.value) <= 1000):
+             raise ValueError("指数过大（上限 1000）")
      return _OPS[type(node.op)](_eval(node.left), _eval(node.right))
```

```diff
- except (SyntaxError, ValueError, TypeError) as exc:
+ # ② except 显式加上 OverflowError
+ except (SyntaxError, ValueError, TypeError, OverflowError) as exc:
      return ToolResult(content=f"计算失败：{exc}", is_error=True)
```

**修正后实测**：`2**100000` / `2**10**10` / `9**9**9` 全部被 `ValueError: 指数过大（上限 1000）` 拒掉，危险表达式拦截仍 5/5。

> **这条的经验比修复本身更重要**：我在同一份文档里刚写完 §1.1"要为某条约束写防御代码之前先实测它"，紧接着就在自己的代码里写了**一条自以为有效、实则无效的保护**。
> **"我加了保护"和"保护真的生效"是两件事**——这已经是本项目第四次遇到同类问题了（阶段 2 的假测试、阶段 3 的漏状态转换、阶段 4 的假通过测试、这里是无效保护）。
> 唯一可靠的检验方式始终是：**构造能触发它的输入，实际跑一遍**。

### 1.4 思考模式必须显式关闭（阶段 4 的结论在 Agent 场景同样成立）

Agent 会做**多轮** LLM 调用。如果每轮都开思考模式，成本与延迟会成倍放大（阶段 0 实测：思考模式让 completion token 涨 5 倍、延迟涨 2.5 倍）。

**Agent 场景下每轮都必须显式传 `thinking: {"type": "disabled"}`。** 注意 DeepSeek 的思考模式**默认开启**，不传就是开的。

### 1.5 为什么不用 LangChain / LangGraph

阶段 6 已经实测过一次"框架静默失效"（DeepEval 的忠实度指标判对 1/4，但看起来完全正常）。同样的风险在这里更严重：

| 风险 | 说明 |
| --- | --- |
| **黑盒 prompt** | Agent 框架内部有自己的提示词（决定"何时调用工具""如何格式化"）。出问题时你面对的是一个你无法读的 prompt |
| **难以控制成本** | 框架可能插入额外的 LLM 调用（如"判断是否需要工具"），你的成本模型会失准 |
| **依赖体积与版本冲突** | 阶段 6 已实测 `ragas` 因 `langchain_community` 变更而直接崩 |
| **自写只要 150 行** | Function Calling 的循环本身很简单：调模型 → 有 tool_calls 就执行 → 结果回传 → 再调，直到没有 tool_calls |

**自写循环的收益**：每一行都可读、每个 token 都可计入成本表、每个决策点都能加自己的保护（轮次上限、成本上限、超时）。

## 4. 工具层

### 4.1 工具契约（`app/tools/base.py`）

```python
"""工具的统一契约。

★ 三条设计原则（都由实测得出，见 §1.2）：
1. **错误是结果，不是异常**：工具内部异常必须转成 {"error": "..."} 返回，
   让模型读懂并自我修正（实测：模型确实会修正）。
2. **描述必须互斥且写明禁用场景**：实测模型会因描述重叠而错调工具。
3. **返回值要有长度上限**：工具结果会进 context，超长会挤掉真正的上下文。
"""

from dataclasses import dataclass
from typing import Any, Protocol


@dataclass
class ToolResult:
    """工具执行结果。永远不会抛异常给 agent 循环。"""

    content: str                      # 给模型看的文本
    is_error: bool = False
    # 供 chat_logs.agent_tools 统计与 trace 使用
    meta: dict[str, Any] | None = None


class Tool(Protocol):
    name: str
    description: str                  # ★ 必须写明"什么时候不要用"
    parameters: dict                  # JSON Schema

    async def run(self, **kwargs: Any) -> ToolResult: ...

    def to_openai_schema(self) -> dict:
        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description,
                "parameters": self.parameters,
            },
        }
```

### 4.2 工具一：`search_kb`（包装阶段 4 的检索）

```python
# app/tools/search_kb.py
"""知识库检索工具。包装阶段 4 的 retrieval.search，签名与行为不变。"""

from typing import Any

from sqlalchemy.ext.asyncio import AsyncSession

from app.clients.embedding import EmbeddingClient
from app.clients.rerank import RerankClient
from app.core.config import settings
from app.services.retrieval import search
from app.tools.base import ToolResult


class SearchKBTool:
    name = "search_kb"
    description = (
        "在用户的知识库中检索资料。当问题涉及用户上传的文档内容（政策、说明、条款、流程等）时使用。"
        "不要用它回答常识性问题或做数学计算——计算请用 calc。"
        "如果一次没检索到，可以换一个检索词再试一次，但不要反复用同样的词。"
    )
    parameters = {
        "type": "object",
        "properties": {
            "query": {
                "type": "string",
                "description": "检索词。用完整的问句或关键短语，不要只用一个字。",
            }
        },
        "required": ["query"],
    }

    def __init__(
        self,
        db: AsyncSession,
        embedder: EmbeddingClient | None,
        reranker: RerankClient | None,
        owner_id: int,
    ) -> None:
        self._db = db
        self._embedder = embedder
        self._reranker = reranker
        self._owner_id = owner_id
        # ★ 记录本次工具调用召回了哪些切片，供引用回填（tool 结果里没有 chunk_id，
        #   因为模型不需要看到 id，但接口的 citations 需要）
        self.last_chunk_ids: list[int] = []

    async def run(self, **kwargs: Any) -> ToolResult:
        query = (kwargs.get("query") or "").strip()
        if not query:
            return ToolResult(content="错误：缺少必填参数 query（应为非空字符串）", is_error=True)

        try:
            # ★ 复用阶段 4 的检索（owner_id 隔离、只查 ready 文档、混合检索 + rerank）
            chunks = await search(
                self._db,
                owner_id=self._owner_id,
                question=query,
                embedder=self._embedder,
                reranker=self._reranker,
            )
        except Exception as exc:                     # noqa: BLE001
            # ★ 不抛异常：转成可读错误，模型会自己换词重试（§1.2 实测）
            return ToolResult(content=f"检索失败：{type(exc).__name__}", is_error=True)

        self.last_chunk_ids = [c.chunk_id for c in chunks]

        if not chunks:
            return ToolResult(
                content="知识库中没有找到与该检索词相关的内容。可以换一种说法再试。",
                meta={"hits": 0},
            )

        # ★ 给模型的格式：带编号 + 出处，便于它在回答里引用
        lines = [
            f"[{i}] 来源《{c.document_title}》第 {c.seq + 1} 段：{c.content}"
            for i, c in enumerate(chunks, start=1)
        ]
        text = "\n\n".join(lines)
        if len(text) > settings.agent_tool_result_max_chars:
            text = text[: settings.agent_tool_result_max_chars] + "\n…（已截断）"
        return ToolResult(content=text, meta={"hits": len(chunks)})
```

### 4.3 工具二：`calc`（安全求值，**绝不用 `eval()`**）

```python
# app/tools/calc.py
"""数学计算工具。

★ 安全实现：用 ast 白名单求值，**绝不用 eval()**。
  eval("__import__('os').system('rm -rf /')") 是真实存在的攻击面，
  而这里的表达式来自**模型生成的字符串**——不能信任。

实测（文档 §7.1）：正常运算全部正确，且 __import__ / open / 条件表达式 /
列表下标等全部被拒。
"""

import ast
import operator
from typing import Any

from app.tools.base import ToolResult

# 只允许这些运算符
_OPS = {
    ast.Add: operator.add,
    ast.Sub: operator.sub,
    ast.Mult: operator.mul,
    ast.Div: operator.truediv,
    ast.FloorDiv: operator.floordiv,
    ast.Mod: operator.mod,
    ast.Pow: operator.pow,
    ast.USub: operator.neg,
    ast.UAdd: operator.pos,
}


def safe_eval(expr: str) -> float:
    """对算术表达式求值。不允许任何名字、属性访问、函数调用、容器。"""
    def _eval(node: ast.AST) -> float:
        if isinstance(node, ast.Expression):
            return _eval(node.body)
        if isinstance(node, ast.Constant):
            if isinstance(node.value, (int, float)) and not isinstance(node.value, bool):
                return float(node.value)
            raise ValueError("只允许数字字面量")
        if isinstance(node, ast.BinOp) and type(node.op) in _OPS:
            # ★ 指数必须在**计算之前**限制：2**100000 会在 float() 转换时抛 OverflowError
            #   （实测 0.00 秒抛出，不卡死，但会让异常逃出工具、崩掉 agent 循环）
            if isinstance(node.op, ast.Pow):
                right = node.right
                if not (isinstance(right, ast.Constant)
                        and isinstance(right.value, int)
                        and abs(right.value) <= 1000):
                    raise ValueError("指数过大（上限 1000）")
            return _OPS[type(node.op)](_eval(node.left), _eval(node.right))
        if isinstance(node, ast.UnaryOp) and type(node.op) in _OPS:
            return _OPS[type(node.op)](_eval(node.operand))
        raise ValueError(f"不允许的语法：{type(node).__name__}")

    tree = ast.parse(expr, mode="eval")          # 解析失败会抛 SyntaxError
    value = _eval(tree)
    if abs(value) > 1e15:
        raise ValueError("结果超出可计算范围")
    return value


class CalcTool:
    name = "calc"
    description = (
        "对数学表达式求值，支持 + - * / // % ** 和括号。"
        "仅用于需要精确数值结果的场景（折扣后价格、单价乘数量、百分比、差值）。"
        "不要用它查资料——查资料请用 search_kb；也不要传入单位或文字。"
    )
    parameters = {
        "type": "object",
        "properties": {
            "expr": {
                "type": "string",
                "description": "纯数学表达式，例如 (99 * 0.9) + 15",
            }
        },
        "required": ["expr"],
    }

    async def run(self, **kwargs: Any) -> ToolResult:
        expr = (kwargs.get("expr") or "").strip()
        if not expr:
            return ToolResult(content="错误：缺少必填参数 expr", is_error=True)
        try:
            value = safe_eval(expr)
        except ZeroDivisionError:
            return ToolResult(content="计算错误：除数为零", is_error=True)
        except (SyntaxError, ValueError, TypeError, OverflowError) as exc:
            # ★ OverflowError 必须显式捕获：2**100000 抛的是它，不是 ValueError。
            #   漏了它，异常会冒泡出工具 → agent 循环崩 → 用户看到 500。
            #   （实测：文档初版漏了，测试脚本直接崩在 except 之外）
            return ToolResult(content=f"计算失败：{exc}", is_error=True)
        # 结果同时给"可读值"和"原始值"，避免模型把 89.10000000000001 抄进回答
        return ToolResult(content=f"{expr} = {round(value, 10):g}", meta={"value": value})
```

## 5. Agent 循环（本阶段核心）

```python
# app/services/agent.py
"""Agent 循环：LLM ↔ 工具，直到模型给出最终回答或触发保护条件。

★ 这不是"把 LangChain 换个写法"，而是刻意保持**完全透明**：
  每一步的输入输出、每次 LLM 调用的 token 与成本、每次工具调用的耗时，
  都在你能读到的代码里，都能写进 chat_logs（阶段 6 的评估体系需要它）。
"""

import asyncio
import json
import logging
import time
from collections import Counter
from dataclasses import dataclass, field
from typing import Any

from sqlalchemy.ext.asyncio import AsyncSession

from app.clients.embedding import EmbeddingClient
from app.clients.llm import LLMClient
from app.clients.rerank import RerankClient
from app.core.config import settings
from app.services.retrieval import RetrievedChunk
from app.tools import build_tools

logger = logging.getLogger(__name__)

AGENT_SYSTEM_PROMPT = """你是知识库问答助手，可以调用工具来完成任务。

工作方式：
1. 先判断问题需要什么：涉及用户文档内容 → 调 search_kb；需要算数 → 调 calc；
   涉及「今天/最近」等相对时间 → 调 now。
2. 拿到工具结果后判断是否足够回答。不够就再调一次别的工具，但**不要用同样的参数重复调用**。
3. 资料不足时直接说明"根据现有资料无法回答"，**绝不编造**。
4. 最终回答要简洁，并在引用资料处标注 [1] [2] 这样的编号。
"""


@dataclass
class AgentStep:
    """一次工具调用记录，用于 trace 与 chat_logs。"""

    step: int
    tool: str
    arguments: dict
    result_preview: str
    is_error: bool
    latency_ms: int


@dataclass
class AgentRun:
    """一次 Agent 运行的完整结果。"""

    answer: str
    steps: list[AgentStep] = field(default_factory=list)
    citations: list[RetrievedChunk] = field(default_factory=list)
    # 累计 LLM 使用量（多轮之和，这是 Agent 成本统计的关键）
    prompt_tokens: int = 0
    completion_tokens: int = 0
    cached_tokens: int = 0
    cost_yuan: float = 0.0
    llm_calls: int = 0
    latency_ms: int = 0
    # 保护条件是否触发（触发时要如实告知用户，而不是假装正常）
    stopped_reason: str | None = None
    tool_counts: dict[str, int] = field(default_factory=dict)


class AgentRunner:
    def __init__(
        self,
        db: AsyncSession,
        llm: LLMClient,
        *,
        owner_id: int,
        embedder: EmbeddingClient | None = None,
        reranker: RerankClient | None = None,
    ) -> None:
        self._db = db
        self._llm = llm
        self._owner_id = owner_id
        self._tools = build_tools(
            db=db, embedder=embedder, reranker=reranker, owner_id=owner_id
        )
        self._schemas = [t.to_openai_schema() for t in self._tools.values()]

    async def run(
        self,
        question: str,
        *,
        history: list[dict[str, str]] | None = None,
        trace: Any = None,          # 可选的 Langfuse span（阶段 6）
    ) -> AgentRun:
        started = time.perf_counter()
        messages: list[dict[str, Any]] = [
            {"role": "system", "content": AGENT_SYSTEM_PROMPT},
            *(history or []),
            {"role": "user", "content": question},
        ]
        run = AgentRun(answer="")
        call_signatures: Counter[str] = Counter()

        for step in range(1, settings.agent_max_steps + 1):
            # ---------- 保护 3：总超时 ----------
            elapsed = time.perf_counter() - started
            if elapsed > settings.agent_timeout_seconds:
                run.stopped_reason = "timeout"
                break

            # ---------- 调 LLM（★ 显式关闭思考模式，见 §1.4）----------
            result = await self._llm.chat(
                messages,
                tools=self._schemas,          # ★ LLMClient 需要新增 tools 透传
                temperature=0.2,
                thinking=False,
                user_id=f"u{self._owner_id}",
            )
            run.llm_calls += 1
            run.prompt_tokens += result.prompt_tokens
            run.completion_tokens += result.completion_tokens
            run.cached_tokens += result.cached_tokens
            run.cost_yuan += result.cost_yuan

            # ---------- 保护 2：成本上限 ----------
            if run.cost_yuan > settings.agent_max_cost_yuan:
                run.stopped_reason = "cost_limit"
                run.answer = result.content or "（已达单次成本上限，未能给出完整回答）"
                break

            tool_calls = result.raw.get("tool_calls") or []
            if not tool_calls:
                # 没有工具调用 = 模型给出最终回答
                run.answer = result.content
                break

            # ---------- 把 assistant 的 tool_calls 追加进对话 ----------
            assistant_msg: dict[str, Any] = {
                "role": "assistant",
                "content": result.content or "",
                "tool_calls": tool_calls,
            }
            # ★ 回传 reasoning_content：当前 API 不强制（§1.1 实测），
            #   但能让模型复用上一轮推理，属于质量优化。关闭思考模式时该字段为空。
            reasoning = result.raw.get("reasoning_content")
            if reasoning:
                assistant_msg["reasoning_content"] = reasoning
            messages.append(assistant_msg)

            # ---------- 逐个执行工具 ----------
            for call in tool_calls:
                name = call["function"]["name"]
                raw_args = call["function"].get("arguments") or "{}"
                try:
                    args = json.loads(raw_args)
                except json.JSONDecodeError:
                    args = {}
                    tool_result_content = f"错误：参数不是合法 JSON（收到 {raw_args[:80]}）"
                    is_error = True
                else:
                    # ---------- 保护 4：重复调用检测 ----------
                    signature = f"{name}:{json.dumps(args, sort_keys=True, ensure_ascii=False)}"
                    call_signatures[signature] += 1
                    if call_signatures[signature] > settings.agent_repeat_call_limit:
                        messages.append({
                            "role": "tool", "tool_call_id": call["id"],
                            "content": "错误：你已经用完全相同的参数调用过这个工具多次，"
                                       "请换一个思路或直接基于已有信息回答。",
                        })
                        run.stopped_reason = "repeat_call"
                        continue

                    tool = self._tools.get(name)
                    t0 = time.perf_counter()
                    if tool is None:
                        tool_result_content = f"错误：不存在的工具 {name}"
                        is_error = True
                        meta = None
                    else:
                        tr = await tool.run(**args)
                        tool_result_content = tr.content
                        is_error = tr.is_error
                        meta = tr.meta
                    tool_ms = int((time.perf_counter() - t0) * 1000)

                    run.steps.append(AgentStep(
                        step=step, tool=name, arguments=args,
                        result_preview=tool_result_content[:200],
                        is_error=is_error, latency_ms=tool_ms,
                    ))
                    if trace is not None:
                        trace.update(metadata={
                            f"tool_step_{step}_{name}": {
                                "args": args, "is_error": is_error,
                                "latency_ms": tool_ms, "preview": tool_result_content[:120],
                            }
                        })

                messages.append({
                    "role": "tool",
                    "tool_call_id": call["id"],
                    "content": tool_result_content,
                })

            # 每轮把最新工具结果回灌；最后一轮结束仍未给出回答则由下面兜底
        else:
            # for 循环正常走完（用尽轮次）——不是 break 出来的
            run.stopped_reason = "max_steps"

        # ---------- 兜底：超过轮次/超时且没有回答时，让模型"就现有信息作答" ----------
        if not run.answer:
            messages.append({
                "role": "user",
                "content": "请立即基于目前已有的信息给出最终回答，不要再调用任何工具。"
                           "如果信息不足，请明确说明无法回答。",
            })
            final = await self._llm.chat(messages, temperature=0.2, thinking=False,
                                        user_id=f"u{self._owner_id}")
            run.llm_calls += 1
            run.prompt_tokens += final.prompt_tokens
            run.completion_tokens += final.completion_tokens
            run.cached_tokens += final.cached_tokens
            run.cost_yuan += final.cost_yuan
            run.answer = final.content or "抱歉，我没能完成这个任务。"

        # ---------- 汇总引用：从 search_kb 工具收集 chunk_ids 再回表取内容 ----------
        search_tool = self._tools.get("search_kb")
        if search_tool is not None and getattr(search_tool, "last_chunk_ids", None):
            run.citations = await self._load_citations(search_tool.last_chunk_ids)

        run.tool_counts = dict(Counter(s.tool for s in run.steps))
        run.latency_ms = int((time.perf_counter() - started) * 1000)

        logger.info(
            '{"event":"agent_run","user":%s,"steps":%s,"llm_calls":%s,'
            '"tools":"%s","cost_yuan":%s,"latency_ms":%s,"stopped":%s}',
            self._owner_id, len(run.steps), run.llm_calls,
            json.dumps(run.tool_counts, ensure_ascii=False),
            round(run.cost_yuan, 6), run.latency_ms, run.stopped_reason,
        )
        return run

    async def _load_citations(self, chunk_ids: list[int]) -> list[RetrievedChunk]:
        """按 chunk_id 回表取切片（复用阶段 4 的取数逻辑，带 owner 校验）。"""
        from sqlalchemy import select

        from app.models.chunk import Chunk
        from app.models.document import Document

        stmt = (
            select(Chunk, Document.title)
            .join(Document, Document.id == Chunk.document_id)
            .where(Chunk.id.in_(chunk_ids), Chunk.owner_id == self._owner_id)  # ★ 越权防线
            .where(Document.status == "ready")
        )
        rows = {c.id: (c, title) for c, title in (await self._db.execute(stmt)).all()}
        out: list[RetrievedChunk] = []
        for cid in chunk_ids:
            item = rows.get(cid)
            if item is None:
                continue
            c, title = item
            out.append(RetrievedChunk(
                chunk_id=c.id, document_id=c.document_id, document_title=title,
                seq=c.seq, content=c.content, score=0.0,
            ))
        return out
```

### 5.1 四层保护（都必须有）

| # | 保护 | 参数 | 不做会怎样 |
| --- | --- | --- | --- |
| 1 | **最大轮次** | `agent_max_steps=6` | 模型可能陷入"检索→没找到→换个词再检索"的循环，无限烧钱 |
| 2 | **成本上限** | `agent_max_cost_yuan=0.05` | 单次问答成本不可预测（快速路径约 0.0005 元，Agent 理论无上界） |
| 3 | **总超时** | `agent_timeout_seconds=60` | 用户等 3 分钟还没响应 |
| 4 | **重复调用检测** | `agent_repeat_call_limit=2` | 同样的参数重复调用同一工具是死循环的典型形态 |

**关键设计：保护触发时要"如实告知"而不是"假装正常"。**

```python
run.stopped_reason = "max_steps"   # 记进 chat_logs，也在接口响应里返回
```

如果触发上限后直接返回一个不完整的答案，用户不知道发生了什么，**你也不知道该调什么参数**。

### 5.2 兜底作答（`for...else` 那个分支）

轮次用尽但模型还在调工具时，**追加一条消息让它"就现有信息作答"**，而不是返回空。

**实测参考**：这条兜底消息在测 `reasoning_content` 约束时被我实际观察到过——模型会照做（哪怕信息不足，它也会明确说"无法回答"）。

### 5.3 `LLMClient` 需要的改动

现有 `chat()` 不支持 `tools` 参数，需要：

```python
# app/clients/llm.py 的 chat() 增加
async def chat(
    self, messages, *, temperature=0.3, max_tokens=None, user_id=None,
    json_mode=False, thinking=None,
    tools: list[dict] | None = None,      # ★ 新增
) -> LLMResult:
    ...
    if tools:
        payload["tools"] = tools
        payload["tool_choice"] = "auto"    # 显式声明，默认值可能变
    ...
```

**`LLMResult.raw` 已经保留了完整响应**（阶段 0 就存了），所以 `result.raw.get("tool_calls")` 能直接取到——**不需要改 `_parse()`**。这是阶段 0 那个"保留 raw"决定的又一次获益。

### 6.1 流式版本（可选，推荐做）

Agent 的多步特性让流式**更有价值**（用户能看到"正在检索…正在计算…"）。复用阶段 2 的 SSE 基础设施：

```
event: meta        {"session_id": 12, "mode": "agent"}
event: step        {"step": 1, "tool": "search_kb", "status": "running"}
event: step        {"step": 1, "tool": "search_kb", "status": "done", "hits": 3, "latency_ms": 45}
event: step        {"step": 2, "tool": "calc", "status": "done", "latency_ms": 2}
event: delta       {"text": "根据资料，折扣后价格是…"}
event: citations   {"citations": [...]}
event: done        {"usage": {...}, "agent_steps": 2, "stopped_reason": null}
```

**`step` 事件是本阶段 SSE 的新增**：它让"Agent 在工作"这件事**可见**——这比一个转圈的 loading 有价值得多。

**实现提示**：`AgentRunner.run()` 目前返回最终 `AgentRun`，要做流式需要改成**异步生成器**（yield 事件）。建议做法：把 `run()` 重构成 `run_stream()`（yield `("step", data)` / `("answer", text)`），再保留一个 `run()` 包装它（收集事件、返回 `AgentRun`）给非流式端点用。**这样两条路径共用同一套循环逻辑**。

## 7. 缓存、成本与配额

### 7.1 为什么 Agent 默认不接阶段 1 的答案缓存

阶段 1 的缓存键是 `(owner_id, 归一化问题, 窗口指纹, 检索指纹)`。Agent 场景下**检索指纹无法预先算**——因为要不要检索、检索几次、用什么词，都是模型在运行中决定的。

**三个选择**：

| 方案 | 取舍 |
| --- | --- |
| **不缓存**（本阶段选择） | 最简、语义最安全；代价是重复问题重复付费 |
| 缓存"最终回答"，键用 `(问题, 窗口指纹)` | 命中率高；**但风险大**——工具结果可能随时间变化（`now` 工具每次都不同） |
| 缓存"工具结果"而非回答 | 更细粒度、更安全；实现较复杂（要给每次工具调用单独做键） |

**建议先不缓存**，用 `chat_logs` 观察 Agent 路径的真实重复率，再决定。**这与阶段 1 处理缓存的方式一致：先用数据说话。**

### 7.2 成本必须单独统计

Agent 路径的成本结构与快速路径完全不同：

```sql
-- 两条路径的成本对比（阶段 5 必查）
SELECT
  is_agent,
  count(*) AS 次数,
  round(avg(cost_yuan)::numeric, 6) AS 平均成本,
  round(avg(latency_ms)) AS 平均延迟,
  round(avg(agent_steps)::numeric, 1) AS 平均步数
FROM chat_logs
GROUP BY is_agent;
```

**这张表是你判断"Agent 值不值得保留"的依据。** 如果 Agent 的平均成本是快速路径的 10 倍、但只多回答了 5% 的问题，那就该把它做成显式选项（本阶段正是这么做的）。

### 7.3 配额要覆盖 Agent

Agent 一次问答可能消耗 3–6 次 LLM 调用的额度。两种处理：

| 方案 | 说明 |
| --- | --- |
| **每次 Agent 问答扣 1 次配额**（当前选择） | 简单；但用户可以靠 Agent 绕过配额 |
| 按实际 LLM 调用次数扣 | 更精确；需要改 `check_daily_quota` 的语义 |

**建议先用方案 1**，同时在 `chat_logs` 里记录 `llm_calls`，观察真实用量后再决定是否改精确扣减。

## 8. 测试策略

### 8.1 不需要真实 LLM（用可编程的假客户端）

Agent 循环是**纯逻辑**，可以用假 LLM 精确驱动：

```python
class ScriptedLLM:
    """按剧本返回响应的假 LLM：第 N 次调用返回第 N 个剧本。

    ★ 这是测试 agent 循环的关键工具：它能精确构造
      「调工具 → 再调工具 → 给答案」「调不存在的工具」「循环调用」
      「参数非法 JSON」等各种路径，而不需要真实模型配合。
    """

    def __init__(self, script: list[dict]):
        self.script = script
        self.calls: list[dict] = []
        self._i = 0

    async def chat(self, messages, **kwargs):
        self.calls.append({"messages": list(messages), **kwargs})
        step = self.script[min(self._i, len(self.script) - 1)]
        self._i += 1
        return LLMResult(
            content=step.get("content", ""),
            prompt_tokens=100, completion_tokens=20, cost_yuan=0.0002,
            raw={"tool_calls": step.get("tool_calls"), "reasoning_content": step.get("reasoning")},
        )
```

### 8.2 必须覆盖的测试

| 测试 | 剧本 | 断言要点 |
| --- | --- | --- |
| **直接回答**（不用工具） | 第 1 次返回 content，无 tool_calls | `steps == []`、`llm_calls == 1` |
| **单工具** | ①调 search_kb ②给答案 | `steps == 1`、`tool_counts == {"search_kb": 1}`、citations 非空 |
| **多工具串联** | ①调 search_kb ②调 calc ③给答案 | `llm_calls == 3`、两个工具都记录 |
| **★ 工具报错后自我修正** | ①调 calc（非法表达式）②调 calc（修正）③给答案 | 第 1 步 `is_error=True`，第 2 步成功（§1.2 的正面用例） |
| **★ 超过最大轮次** | 每次都返回 tool_calls | `stopped_reason == "max_steps"`、`llm_calls == max_steps + 1`（含兜底那次） |
| **★ 成本上限** | 每次返回高成本 + tool_calls | `stopped_reason == "cost_limit"` 且**提前退出** |
| **★ 重复调用检测** | 反复用**完全相同参数**调同一工具 | 第 3 次起被拒、`stopped_reason == "repeat_call"` |
| **不存在的工具** | 返回一个没注册的工具名 | 该步 `is_error=True`，循环继续不崩 |
| **参数不是合法 JSON** | `arguments` 传 `"not json"` | 该步 `is_error=True`，循环继续 |
| **越权防线** | search_kb 返回他人文档的 chunk_id | citations **不含**他人切片（`_load_citations` 的 owner 校验） |
| **思考模式必须关** | 断言传给 LLM 的 kwargs | `thinking is False`（§1.3，防成本爆炸） |
| **tools 透传** | 断言第 1 次调用的 kwargs | `"tools" in kwargs`、含三个工具名 |

### 8.3 工具单测（纯函数优先）

| 工具 | 用例 |
| --- | --- |
| `calc` | 正常运算；**`__import__` / `open` / 列表下标 / 条件表达式全部被拒**；除零；空参数；**`2**1000` / `2**100000` / `2**10**10` / `9**9**9` 全部被拒且不抛 `OverflowError`**（§1.3 实测的边界）；`True` / `'abc'` / 自由变量被拒 |
| `now` | 返回北京时间格式；含星期 |
| `search_kb` | 空 query → 可读错误；检索抛异常 → 可读错误（**不冒泡**）；超长结果被截断；无命中时的提示文案 |
| `to_openai_schema` | 每个工具的 schema 结构合法、`required` 与 `parameters` 一致 |

### 8.4 一条反脆弱断言

`test_tool_descriptions_are_mutually_exclusive` —— 检查每个工具描述里**含"不要用它"这类边界声明**：

```python
def test_tool_descriptions_state_when_not_to_use():
    """★ §1.2 实测：工具描述重叠会导致错调。
    强制每个工具都声明禁用场景——这是防"新增工具时忘记写边界"的机械检查。"""
    for tool in build_tools(db=None, embedder=None, reranker=None, owner_id=1).values():
        assert "不要" in tool.description or "仅在" in tool.description, (
            f"工具 {tool.name} 的描述缺少使用边界声明（§1.2：描述重叠会导致错调）"
        )
```

**这条测试的价值**：它把一条**设计约定**变成了自动检查。将来加第四个工具时，如果忘写边界，测试立刻红。

### 9.2 所以要给评测集补一类用例

```yaml
# app/evals/agent_cases.yaml —— 专测 Agent 增量
cases:
  - id: discount_calc
    question: 订单 299 元，打九折再减 20 元是多少？
    expected_tools: []            # 纯计算，不该检索
    expect_tool: calc
    key_points: ["结果等于 249.1"]
    tags: [计算]

  - id: policy_plus_calc
    question: 我买了两件 89 元的商品，满 99 包邮，需要付运费吗？一共多少钱？
    expect_tool: [search_kb, calc]   # ★ 必须两跳
    key_points: ["满 99 元包邮", "总计 178 元，无需运费"]
    tags: [多跳, 计算]

  - id: relative_time
    question: 今天是几号？发票还能申请吗？
    expect_tool: [now, search_kb]
    key_points: ["需要先确认今天日期", "发票需在下单后 7 天内申请"]
    tags: [相对时间, 多跳]
```

**`expect_tool` 字段是 Agent 评测的关键**：它让"有没有调用正确的工具"变成可断言的东西——**这比只看最终答案更能定位问题**（答案对了但工具调错了，是运气；工具调对了答案错，是推理问题）。

### 9.3 Agent 专属指标

| 指标 | 定义 | 为什么重要 |
| --- | --- | --- |
| **工具选择准确率** | 实际调用的工具集合 == `expect_tool` | 定位"选错工具"这类失败 |
| **步数** | 平均 tool 调用轮数 | 效率；步数异常高说明在来回试 |
| **保护触发率** | `stopped_reason != null` 的比例 | **这个指标高说明项目不可用**——用户在频繁碰到上限 |
| **成本倍率** | Agent 平均成本 / 快速路径平均成本 | 决定"Agent 该不该默认开" |

## 11. 风险与取舍

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| **成本不可预测** | 快速路径约 0.0005 元，Agent 理论无上界 | 成本上限 + 轮次上限；`chat_logs` 单独统计 |
| **延迟长** | 2–10s，用户可能以为卡死 | 做流式 `step` 事件让过程可见；或前端明确提示"正在思考" |
| **循环不收敛** | 反复检索同一内容 | 重复调用检测 + 轮次上限 + 兜底作答 |
| **工具描述漂移** | 新增工具时忘写边界 → 错调 | 反脆弱测试（§8.4）机械检查 |
| **缓存失效** | Agent 路径不接阶段 1 的缓存 | 先用数据看重复率（§7.1），再决定要不要做工具级缓存 |
| **配额被绕过** | 一次 Agent 问答消耗多次 LLM 调用但只扣 1 次配额 | 记录 `llm_calls` 观察；必要时改精确扣减 |
| **评测集不覆盖 Agent 增量** | 阶段 6 的 24 条用例快速路径已满分 | 补 `agent_cases.yaml`（§9.2），重点是**计算/时间/多跳**三类 |
